1. OVERVIEW
================================================================================

The Eventra Admin module provides administrative tools for system management.
Admin-only features are accessible to users with the 'admin' role.

Access Requirements:
- User must be authenticated
- User must have email verified
- User must have role = 'admin'

Base URL: http://localhost:8000 (development)

================================================================================
2. ADMIN DASHBOARD
================================================================================

URL: /admin/dashboard
Controller: AdminDashboardController.php
Frontend: resources/js/pages/Admin/AdminDashboard.tsx

DESCRIPTION:
------------
The Admin Dashboard provides a comprehensive overview of the entire system,
including user statistics, event metrics, support tickets, and recent activities.

FEATURES:
---------
a) Statistics Overview Cards:
   - Total Users: Shows total count with breakdown (admins, managers, members)
   - Total Events: Shows active, past, and draft event counts
   - Support Tickets: Displays pending and resolved ticket counts
   - System Health: Shows current system status

b) Charts & Visualizations:
   - User Growth Chart: Area chart showing user registration over last 6 months
   - Event Status Distribution: Pie chart showing active/past/draft events
   - Ticket Status Distribution: Shows pending/in-progress/resolved tickets

c) Quick Actions Panel:
   - Manage Users: Navigate to user management
   - Activity Logs: View system activity history
   - Support Tickets: Manage user support requests
   - Analytics & Reports: Access detailed analytics

d) Recent Activity Feed:
   - Shows last 10 system activities
   - Displays activity type, description, user, and timestamp
   - Color-coded icons for user/event/ticket activities

API ENDPOINT:
-------------
GET /api/admin/dashboard/stats
Returns JSON with all dashboard statistics

3. MANAGE USERS
================================================================================

URL: /admin/manage-users
Controller: AdminManageUsersController.php
Frontend: resources/js/pages/Admin/ManageUsers.tsx

DESCRIPTION:
------------
Full user management system allowing admins to create, view, edit, and delete
any user in the system regardless of their role.

FEATURES:
---------

a) User Statistics Cards:
   - Total Users count
   - Admins count (red badge)
   - Managers count (purple badge)
   - Members count (green badge)

b) Add New User:
   - Click "Add User" button to open form
   - Required fields: Name, Email (UTM format), Matric ID, Role, Password
   - Optional fields: Secondary email, Phone, Gender, Faculty, Nationality
   - Profile picture upload (PNG, JPG, GIF up to 2MB)
   - Passwords are auto-hashed with bcrypt
   - Admin-created users are auto-verified

c) User List Table:
   - Displays: Profile picture, Name, Email, Matric ID, Role, Joined Date
   - Instant client-side search (name, email, matric ID)
   - Role filter buttons (All, Admins, Managers, Members)
   - Checkbox selection for bulk actions
   - Actions: View, Edit, Delete

d) BULK ACTIONS (NEW):
   - Select multiple users via checkboxes
   - "Select All" checkbox in table header
   - Bulk action bar appears when users are selected
   - Bulk Delete: Delete multiple users at once (cannot delete self)
   - Bulk Role Change: Change role for multiple users to:
     * Member
     * Manager
     * Admin
   - Confirmation dialogs for all bulk actions
   - Activity logging for bulk operations

e) View User Details:
   - Modal popup with full user information
   - Shows all profile fields and timestamps

f) Edit User:
   - Pre-populates form with existing data
   - Password change is optional during edit
   - Updates profile picture if new one uploaded

g) Delete User:
   - Confirmation dialog before deletion
   - Cannot delete own account (self-protection)
   - Removes profile picture and participant records
   - Logs deletion activity

API ENDPOINTS:
--------------
GET    /admin/manage-users           - List all users (Inertia page)
POST   /admin/users                  - Create new user
GET    /admin/users/{id}             - Get user details (JSON)
PUT    /admin/users/{id}             - Update user
DELETE /admin/users/{id}             - Delete user
POST   /admin/users/bulk-delete      - Bulk delete users (NEW)
POST   /admin/users/bulk-role        - Bulk change user roles (NEW)
GET    /api/admin/users/statistics   - Get user statistics (JSON)

VALIDATION RULES:
-----------------
- email: Required, must be @graduate.utm.my format
- matric_id: Required, unique
- role: Required, must be admin/manager/member
- password: Required for new users, min 8 characters, must confirm
- profile_picture: Optional, image only, max 2MB

4. ACTIVITY LOGS
================================================================================

URL: /admin/activity-logs
Controller: ActivityLogController.php
Model: ActivityLog.php
Frontend: resources/js/pages/Admin/ActivityLogs.tsx

DESCRIPTION:
------------
Comprehensive audit trail system that logs all significant actions in the
system for security monitoring and compliance purposes.

FEATURES:
---------

a) Quick Statistics:
   - Total Logs count
   - Recent logs (current page)
   - Resource types tracked
   - Active users count

b) Advanced Filtering:
   - Search by keywords (description, action, user name)
   - Filter by action category (user, event, auth, etc.)
   - Date range filter (from/to)
   - User filter dropdown
   - Resource type filter

c) Activity Log Table:
   - When: Relative time + exact timestamp
   - Actor: User avatar + name (or "System")
   - Activity: Action badge with color coding
   - Resource: Type and ID
   - Memo: Description preview
   - View: Detail button

d) Log Detail Modal (Audit Inspector):
   - Full log metadata
   - Origin IP address
   - Object/Resource type
   - Action tag
   - Memo summary
   - State Transformation (Diff Viewer)
     - Shows old values vs new values
     - Highlights changed attributes
   - Environment signature (User Agent)
   - Copy raw metadata to clipboard

e) Export Functionality:
   - Export to CSV with filters applied
   - Includes: ID, Timestamp, User, Action, Resource, Description, IP

LOGGED ACTIVITIES:
------------------
- user.created: When new user is added
- user.updated: When user profile is modified
- user.deleted: When user is removed
- user.bulk_deleted: When multiple users deleted (NEW)
- user.bulk_role_changed: When multiple user roles changed (NEW)
- auth.login: When user logs in
- auth.logout: When user logs out
- event.created: When new event is created
- event.updated: When event is modified
- event.deleted: When event is deleted
- support.ticket.responded: When admin responds to ticket
- And more...

API ENDPOINTS:
--------------
GET /admin/activity-logs                  - List logs (paginated, 25/page)
GET /admin/activity-logs/export           - Export to CSV
GET /admin/activity-logs/{id}             - Get single log details

5. CONTACT SUPPORT SYSTEM
================================================================================

USER SIDE:
----------
URL: /contact-support
Controller: ContactSupportController.php
Frontend: resources/js/pages/ContactSupport.tsx

ADMIN SIDE:
-----------
URL: /admin/support-tickets
Controller: AdminSupportController.php
Frontend: resources/js/pages/Admin/SupportTickets.tsx
          resources/js/pages/Admin/SupportTicketDetail.tsx

DESCRIPTION:
------------
Support ticket system where users can submit support requests and
admins can view, respond, and manage tickets. Features include ticket
categories and admin-controlled priority levels.

USER FEATURES (Contact Support):
--------------------------------
a) Submit Support Ticket Form:
   - Name (pre-filled from profile)
   - Email (pre-filled from profile)
   - Subject (max 255 chars)
   - Category Selection:
     * General Inquiry
     * Technical Issue
     * Account Problem
     * Event Related
     * Payment Issue
     * Other
   - Message (max 2000 chars with counter)
   - Submit button with loading state
   Note: Priority is set by admin when reviewing tickets

b) Success Confirmation:
   - Shows success message after submission
   - Options: Submit another ticket, View my tickets

c) Support History:
   URL: /support-history
   - Lists user's own submitted tickets
   - Shows status, category, priority, and admin responses

ADMIN FEATURES (Support Tickets Management):
--------------------------------------------

a) Statistics Dashboard:
   - Pending tickets count (yellow)
   - In Progress tickets count (blue)
   - Resolved tickets count (green)
   - Total tickets count (purple)

b) Ticket List:
   - Tabbed view: All, Pending, In Progress, Resolved
   - Each ticket shows:
     - Status badge
     - Priority badge (NEW) - with color coding
     - Category badge (NEW)
     - Ticket ID
     - Subject
     - Message preview
     - Submitter name
     - Submission date
   - Click to view details
   - Pagination support

c) Ticket Detail View:
   URL: /admin/support-tickets/{id}
   - Full ticket information
   - User details (name, email, submission date)
   - Category and Priority badges
   - User Message section (displays original message)
   - Status dropdown (Pending/In Progress/Resolved)
   - Priority dropdown (Low/Medium/High/Urgent) - Admin sets priority
   - Admin Response textarea (max 2000 chars)
   - Save Changes button
   - Delete Ticket button
   - Shows last responded by info if previously responded

d) Email Notifications (ENHANCED):
   - User receives notification when admin responds
   - NEW: Dedicated support response email template
     * Shows ticket ID and subject
     * Shows current status
     * Includes full admin response text
     * Shows responder name and timestamp
     * Links to view ticket in support history
     * Professional branded design

TICKET STATUS FLOW:
-------------------
pending -> in_progress -> resolved

TICKET DATA STRUCTURE:
----------------------
{
  "id": number,
  "user_id": number,
  "name": string,
  "email": string,
  "subject": string,
  "message": string,
  "category": "general" | "technical" | "account" | "event" | "payment" | "other",
  "priority": "low" | "medium" | "high" | "urgent",  // Set by admin
  "status": "pending" | "in_progress" | "resolved",
  "admin_response": string | null,
  "responded_by": number | null,
  "responded_at": timestamp | null,
  "created_at": timestamp
}

API ENDPOINTS:
--------------
User Side:
  GET  /contact-support              - Display form
  POST /contact-support              - Submit ticket (with category)
  GET  /support-history              - View own tickets

Admin Side:
  GET    /admin/support-tickets              - List all tickets
  GET    /admin/support-tickets/{id}         - View ticket details
  PUT    /admin/support-tickets/{id}         - Update status/priority/response
  DELETE /admin/support-tickets/{id}         - Delete ticket
